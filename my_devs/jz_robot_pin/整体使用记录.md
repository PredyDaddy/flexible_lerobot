按当前代码，正确流程需要 1 个 Orin 终端和 2 个 x86 终端：

```text
遥操设备 -> 遥操可视化/发布端 -> recorder -> 机器人
                                      -> 保存数据
```

### 手柄连接x86
```bash
conda activate light_tp

python my_devs/my_var_tp/recv_vr_udp.py
```


### 终端 1：Orin 机器人端

```bash
cd /home/data/test/workspace/flexible_lerobot

JZ_UDP_EXECUTOR_ARMED=1 \
bash my_devs/jz_robot_pin/edge/start_pin_replay.sh
```

等到出现：

```text
replay services ready
```

### 终端 2：x86 遥操可视化

这个就是你说的遥操可视化，同时负责接收遥操输入并发布 `target_action`：

```bash
cd /home/luzhuang/cqy/aaa/flexible_lerobot

bash my_devs/jz_robot_pin/x86/start_pin_joystick.sh
```

保持这个终端一直运行。新启动日志应显示 `publish_mode=always`；这会持续发布当前保持目标，
不再要求 recorder 启动后 5 秒内人工按 Grip。Meshcat 使用 30 Hz 整机显示。浏览器打开：

```text
http://127.0.0.1:7000/static/
```

启动后确认日志包含 `target_frequency=30Hz ... model=whole-robot` 和
`visual meshes loaded: 24`。运行状态中的 `meshcat_hz` 应稳定在约 30；旧进程必须重启才能生效。

确认可视化已经出现，并且能收到遥操输入。

### 终端 3：x86 连接机器人并录制三条数据

x86 不需要再单独执行连接命令。下面的 recorder 会连接 Orin、控制机器人并保存数据：

```bash
cd /home/luzhuang/cqy/aaa/flexible_lerobot

DATASET_NAME="jz_robot_pin_real_$(date +%Y%m%d_%H%M%S)" \
EPISODE_TIME_S=10 \
RESET_TIME_S=5 \
RECORD_FPS=30 \
JZ_ROBOT_PIN_ARMED=1 \
I_UNDERSTAND_JZ_ROBOT_PIN_MOVES_ROBOT=1 \
bash my_devs/jz_robot_pin/data_check/record_and_check_3.sh
```

该现场包装器的第一帧和后续相邻 action 关节差值阈值默认均为 `10 rad`，对正常关节范围
等效于放开；录制完成后的自动检查仍记录实际差值，但不会因正常的运控跟随误差失败。

每条数据真正写入第一帧时，终端会打印并语音播报 `Start recording episode 1/2/3`。
reset 阶段 recorder 仍持有遥操控制并继续发送 action，但不会把 reset 帧写入数据集。

它会连续录制三条，每条 10 秒，中间有 5 秒 reset。录制过程中终端 2 的遥操可视化必须持续运行。正常情况下不要按键，让三条自动完成。

看到下面内容表示录制和检查完成：

```text
[record_and_check_3] PASS report=...
```

### 操作结束

先在 x86 的可视化终端按 `Ctrl+C`，然后执行：

```bash
cd /home/luzhuang/cqy/aaa/flexible_lerobot
bash my_devs/jz_robot_pin/stop_teleop.sh
```

最后在 Orin 执行：

```bash
cd /home/data/test/workspace/flexible_lerobot
bash my_devs/jz_robot_pin/edge/stop_pin_replay.sh
```

录制期间不要再运行 `start_teleop.sh` 或 `start_pin_control.sh`，因为 recorder 已经承担了连接和遥操控制循环。
