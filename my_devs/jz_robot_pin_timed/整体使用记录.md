# jz_robot_pin_timed 采集与诊断流程

## 1. 数据链路

```text
Orin ROS state -> UDP 39010 (timed 默认 30 Hz) ----+
                                                   |
Orin RTSP head/left/right -> PyAV timed receiver --+-> recorder -> Parquet + MP4 + timing JSONL
                                                   |
VR -> IK/可视化 -> target action UDP 39030 --------+
                                                   |
                                      command UDP 39020 -> Orin executor
```

Robot 的公开训练字段仍然是 18 维 `observation.state` 和 18 维 `action`。时序诊断不塞进训练
observation，而是单独写入 `meta/timing/episode-*.jsonl`，因此不会改变现有策略输入维度。
每行还保存 `session_id`，以及同一 `observation_sequence` 实际 command 的 packet seq/stamp、mode、transport、
18 维字段数，以及本机 send 完成的 wall/monotonic 时间。

## 2. 上机前只读检查

只读探针适合先确认 state、三路 RTSP 和时序指标。它不需要 command executor。

Orin 终端：

```bash
cd /home/data/test/workspace/flexible_lerobot
bash my_devs/jz_robot_pin_timed/edge/start_pin_state.sh
```

x86 终端：

```bash
cd /home/luzhuang/cqy/aaa/flexible_lerobot

PROBE_DURATION_S=10 \
PROBE_FPS=30 \
bash my_devs/jz_robot_pin_timed/x86/probe_timed_observation.sh
```

默认 JSONL 写到 `my_devs/jz_robot_pin_timed/logs/timed_observation_<timestamp>.jsonl`。末行
`type=summary` 给出：

- `reused_samples`：30 Hz observation loop 重复使用同一 decoder frame 的次数；
- `skipped_decoder_sequences`：两次 observation 之间 decoder 已前进多帧的数量；
- `missing_pts_samples`：RTSP frame 没有可用 PTS 的次数；
- `age_ms_*`：按 state 接收时刻从 buffer 选中的相机帧，在 observation 读取时的年龄；
- `state_receive_skew_ms_*`：camera decoder 输出和 state 接收在 x86 本地时间轴上的差；
- `over_skew_limit_samples`：超过默认 100 ms 诊断阈值的次数。

只看 state，不打开 RTSP：

```bash
STATE_ONLY=1 bash my_devs/jz_robot_pin_timed/x86/probe_timed_observation.sh
```

只看 head 和 right：

```bash
CAMERAS="head right" bash my_devs/jz_robot_pin_timed/x86/probe_timed_observation.sh
```

重要限制：探针、recorder 和 control 都监听 `0.0.0.0:39010`。同一时间只能保留一个 x86 state
消费者，否则 UDP 包可能被不同 socket 分走，诊断结果没有意义。

如果只需要确认 VR UDP 包格式和输入频率，可运行共享解析器的 timed 包装入口：

```bash
conda run --no-capture-output -n lerobot_flex \
  python my_devs/jz_robot_pin_timed/recv_vr_udp.py \
  --host 10.1.42.3 \
  --port 8080
```

这个工具只绑定 VR `8080` 并打印收到的包，不启动 IK、Robot、state 或 command 链路；它不能与
占用同一 VR 端口的正式 joystick publisher 同时运行。

## 3. 正式三终端录制

### 终端 1：Orin state + executor

```bash
cd /home/data/test/workspace/flexible_lerobot

JZ_UDP_EXECUTOR_ARMED=1 \
bash my_devs/jz_robot_pin_timed/edge/start_pin_replay.sh
```

等待 `replay services ready`。

timed edge 包装器默认 `STATE_HZ=30`，匹配 30 FPS 采集；覆盖该值时必须重新评估重复帧比例。

### 终端 2：x86 VR、IK 和整机 Meshcat

```bash
cd /home/luzhuang/cqy/aaa/flexible_lerobot
bash my_devs/jz_robot_pin_timed/x86/start_pin_joystick.sh
```

该脚本复用原 Pin 发布端，默认 target action 发往 `127.0.0.1:39030`。办公机通过 SSH 访问时，
Meshcat 地址使用 x86 实际 IP：

```text
http://<X86_IP>:7000/static/
http://10.1.42.3:7000/static/   # 当前现场示例
```

### 终端 3：x86 recorder

```bash
cd /home/luzhuang/cqy/aaa/flexible_lerobot

DATASET_NAME="jz_robot_pin_timed_real_$(date +%Y%m%d_%H%M%S)" \
EPISODE_TIME_S=10 \
RESET_TIME_S=5 \
RECORD_FPS=30 \
VIDEO_CRF=18 \
JZ_ROBOT_PIN_ARMED=1 \
I_UNDERSTAND_JZ_ROBOT_PIN_MOVES_ROBOT=1 \
bash my_devs/jz_robot_pin_timed/data_check/record_and_check_3.sh
```

默认行为：

- H.264 CRF 18、GOP 2、yuv420p；
- 三条现场包装器把 initial/step joint delta guard 都设为已接受的 `10.0 rad`；
- 三条完成后批量编码视频；
- episode reset 期间继续遥操，但不保存 reset 帧；
- stale target action 直接终止，不用 hold-current 静默污染数据；
- camera/state skew 超过 100 ms 时终止当前采集；
- reused camera frame 默认只记录，不终止；
- 每 30 次 observation 在终端打印一次时序摘要。

`record_and_check_3.sh` 完成后会执行两层检查：

- `check_3_episodes.py`：检查三条 episode、18 维 action/state、视频和动作跟随；
- `check_timing.py`：检查 H.264 CRF 18，并严格核对每个 dataset frame 与 timing JSONL；
- 跨进程 resume 通过 `session_id` 分段检查 observation sequence；
- command 必须属于同一 observation，并检查 mode/transport、18 维字段数和发送完成时间；
- 报告写到 `<dataset_root>/data_check_report.json` 和 `timing_check_report.json`。

只检查已有数据，不连接机器人：

```bash
conda run --no-capture-output -n lerobot_flex \
  python my_devs/jz_robot_pin_timed/data_check/check_timing.py \
  --dataset-root tests/outputs/<dataset_name> \
  --expected-codec h264 \
  --expected-crf 18
```

timed 相机每轮会从缓存中选择 decoder 输出时刻最接近 state 接收时刻的 frame；sidecar 里的 `age_ms`
描述这个被选中 frame 在 observation 读取时的年龄，不是无条件取最新 frame 的年龄。
camera `receive_*` 的阶段写为 `decoder_output_before_pixel_conversion`；它不是 RTSP 网络收包或
传感器曝光时间。

通用 `record.sh` 面向手动和后续严格采集，initial/step guard 默认仍为 `0.02 rad`。不要把三条
包装器的 `10.0 rad` 误认为 Robot 全局默认；直接运行 `record.sh` 时应根据当次现场姿态显式决定
是否覆盖这两个阈值。

## 4. 单独遥操，不录制

Orin 仍先启动 state + executor，然后在 x86：

```bash
cd /home/luzhuang/cqy/aaa/flexible_lerobot

JZ_ROBOT_PIN_ARMED=1 \
I_UNDERSTAND_JZ_ROBOT_PIN_MOVES_ROBOT=1 \
bash my_devs/jz_robot_pin_timed/start_teleop.sh
```

这个入口同时启动无相机的 timed control 和共享 VR/Meshcat 发布端。日志与 PID 独立存放在：

```text
my_devs/jz_robot_pin_timed/logs/
my_devs/jz_robot_pin_timed/run/
```

停止脚本只匹配 timed PID 文件、timed 脚本绝对路径，以及 teleoperate 专用 ID
`--robot.id=jz_robot_pin_timed_control`，不会全局匹配所有 `lerobot_teleoperate`，也不会匹配
timed recorder/replay：

```bash
bash my_devs/jz_robot_pin_timed/stop_teleop.sh
```

录制时不要同时运行 `start_teleop.sh`，recorder 本身已经占用 state、target action 和 command
控制链路。

## 5. 结束顺序

1. x86 recorder 自然完成或 `Ctrl+C`；
2. x86 VR/可视化终端 `Ctrl+C`；
3. 如运行过 timed teleop，执行 `stop_teleop.sh`；
4. Orin 执行 `edge/stop_pin_replay.sh`。

```bash
cd /home/data/test/workspace/flexible_lerobot
bash my_devs/jz_robot_pin_timed/edge/stop_pin_replay.sh
```

edge 包装器和原 Pin 使用同一个 bridge/executor 服务，不是两套并行服务。
