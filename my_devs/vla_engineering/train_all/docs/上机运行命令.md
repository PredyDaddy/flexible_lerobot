# train_all VLASH 上机运行命令

本文记录 `train_all` 5 epochs delay-aware VLASH checkpoint 的上机前 smoke 和真实机器人运行命令。

## 当前默认 checkpoint

```bash
/data/cqy_workspace/flexible_lerobot/my_devs/vla_engineering/train_all/outputs/pi05_so101_delay_lora_r192_delay8_bs8_accum1_5epochs/checkpoints/last/pretrained_model
```

该 `last` 当前指向 `033272`，训练步数为 `33272`，约等于 5 epochs。

## 1. 直接 checkpoint smoke

不启动 HTTP 服务，不连接机器人，只加载 checkpoint 并在数据集样本上生成一个 action chunk。

```bash
cd /data/cqy_workspace/flexible_lerobot && \
bash my_devs/vla_engineering/train_all/scripts/smoke_latest_policy.sh
```

## 2. HTTP 服务链路 smoke

临时启动 policy server，然后用数据集样本请求 `/infer`，验证服务端加载、HTTP 编解码和 action chunk 输出。

```bash
cd /data/cqy_workspace/flexible_lerobot && \
HOST=127.0.0.1 \
PORT=8005 \
NUM_INFERENCE_STEPS=2 \
bash my_devs/vla_engineering/train_all/scripts/smoke_vlash_http_server.sh
```

## 3. 服务端

上机时先开服务端。服务端使用 `vlash_train` 环境，负责加载 PI0.5/VLASH checkpoint 并提供 `/infer`。

```bash
cd /data/cqy_workspace/flexible_lerobot && \
DEFAULT_PROMPT="Put the eraser into the small box" \
PORT=8005 \
NUM_INFERENCE_STEPS=10 \
bash my_devs/vla_engineering/train_all/scripts/serve_vlash_policy.sh
```

## 4. 异步客户端观察模式

先连接机器人、相机和服务端，但不发送动作。该模式用于确认相机、串口、服务端请求、异步预取和 action chunk 都正常。

```bash
cd /data/cqy_workspace/flexible_lerobot && \
HOST=localhost \
PORT=8005 \
EXECUTE_ACTIONS=false \
bash my_devs/vla_engineering/train_all/scripts/run_vlash_async_robot_client.sh \
  --task "Put the eraser into the small box" \
  --robot-id hfy_follower \
  --robot-port /dev/serial/by-id/usb-1a86_USB_Single_Serial_5A7C123192-if00 \
  --calib-dir /home/cqy/.cache/huggingface/lerobot/calibration/robots/so_follower \
  --top-cam /dev/video4 \
  --wrist-cam /dev/video6 \
  --top-cam-fourcc YUYV \
  --wrist-cam-fourcc MJPG \
  --img-width 640 \
  --img-height 480 \
  --fps 30 \
  --run-time-s 10 \
  --max-relative-target 10 \
  --motor-io-retries 10 \
  --action-chunk-steps 40 \
  --prefetch-at-step 20 \
  --max-chunk-execute-steps 50
```

## 5. 异步真正打开动作

观察模式正常后，再打开动作执行。异步客户端会在执行当前 chunk 的同时提前请求下一段 chunk，减少同步等待造成的卡顿。

```bash
cd /data/cqy_workspace/flexible_lerobot && \
HOST=localhost \
PORT=8005 \
EXECUTE_ACTIONS=true \
bash my_devs/vla_engineering/train_all/scripts/run_vlash_async_robot_client.sh \
  --task "Put the eraser into the small box" \
  --robot-id hfy_follower \
  --robot-port /dev/serial/by-id/usb-1a86_USB_Single_Serial_5A7C123192-if00 \
  --calib-dir /home/cqy/.cache/huggingface/lerobot/calibration/robots/so_follower \
  --top-cam /dev/video4 \
  --wrist-cam /dev/video6 \
  --top-cam-fourcc YUYV \
  --wrist-cam-fourcc MJPG \
  --img-width 640 \
  --img-height 480 \
  --fps 30 \
  --run-time-s 60 \
  --max-relative-target 10 \
  --motor-io-retries 10 \
  --action-chunk-steps 40 \
  --prefetch-at-step 20 \
  --max-chunk-execute-steps 50
```

参数含义：

```text
--action-chunk-steps 40
  理想情况下每个 chunk 执行到第 40 步就切换到异步预取好的下一段。

--prefetch-at-step 20
  当前 chunk 执行到第 20 步时采集新 observation 并后台请求下一段 chunk。

--max-chunk-execute-steps 50
  如果下一段 chunk 还没回来，最多吃完当前 chunk 的第 50 步，避免立刻停顿。
```
