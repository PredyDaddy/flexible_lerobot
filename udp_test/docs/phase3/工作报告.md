## 1. 当前结论

截至本报告，Phase 3 已经完成并实测通过以下链路：

```text
Orin ROS state topic
  -> Orin readonly UDP state bridge
  -> x86 JZRobotUDP.get_observation()
  -> x86 jz_robot_udp_hold teleop
  -> action = current observation.state
  -> x86 JZRobotUDP.send_action(dry_run UDP)
  -> Orin Phase 3 command executor(dry_run)
  -> safety gate accepted=True
  -> publish=False
```

这说明：

```text
1. x86 可以稳定拿到 Orin state 和三路 RTSP 图像。
2. lerobot-record 可以用 jz_robot_udp_hold 录制 dry-run dataset。
3. 录到的 action 不是全 0。
4. 录到的 action 与 observation.state 完全一致，是 hold action 语义。
5. x86 dry-run command packet 可以被 Orin Phase 3 executor 接收并接受。
6. dry-run 下 Orin executor 不发布 ROS command topic，机器人不会动。
7. 单关节 +0.001 observation_delta packet dry-run 已通过。
```

尚未完成：

```text
1. armed 模式真实 publish。
2. 真机单包小偏移运动确认。
3. replay active。
4. 长时间 active record。
```

`x86_jz_robot_udp_send_action_check.py` 已支持：

```text

3. --action-source zero
4. --action-source observation_delta
5. --delta-key
6. --delta-value
```

注意：

```text
--action-source observation_delta 必须配合 --no-command-only。
```

原因是 observation_delta 需要先调用 `get_observation()`，再构造：

```text
action = current observation
action[delta_key] += delta_value
```

所以 observation_delta 前必须启动 Orin readonly state bridge。

### 2.3 hold teleop

新增/使用的 hold teleop：

```text
src/lerobot/teleoperators/jz_robot_udp_hold/
```

其语义是：

```text
get_action_from_observation(observation) -> action
```

也就是每一帧 action 直接复制当前 observation 中对应的 joint/gripper 数值。这样录制静止数据时，dataset 的 action 语义是“保持当前姿态”，不是“去 0 位”。

这点非常重要。不要把 `jz_robot_udp_constant` 录出来的全 0 action 直接 replay 到真机。

## 5. 已知现象与排查记录

### 5.1 x86 卡在 observation_check / record connect

现象：

```text
Timed out waiting for the first JZRobot UDP state packet on 0.0.0.0:39010
```

或 x86 输出停在：

```text
[x86 jz_robot_udp observation check] config=...
```

根因：

```text
Orin readonly state bridge 未启动，或状态桥已经异常。
```

处理：

```bash
cd ~/workspace/flexible_lerobot

bash udp_test/server_bash/orin_arm/stop.sh
bash udp_test/server_bash/orin_arm/start.sh
```

检查：

```text
[orin ros state udp bridge] sent seq=1 ...
[orin ros state udp bridge] sent seq=20 ...
```

注意：

```text
x86 侧没有额外后台服务需要先启动。
x86 的 observation_check / record 进程会临时绑定 0.0.0.0:39010 接收 state。
```

如怀疑 x86 端口被占用，可在 x86 查：

```bash
ss -lunp | grep ':39010' || true
```

### 5.2 dataset root 已存在

现象：

```text
FileExistsError: [Errno 17] File exists: 'tests/outputs/jz_robot_udp_hold_phase3_dry_run'
```

根因：

```text
LeRobotDataset.create() 默认 exist_ok=False。
同一个 dataset.root 不能重复创建。
```

处理：

```text
换新的 dataset.root / dataset.repo_id，例如 _002、_003。
不要随便覆盖已有数据。
```

### 5.3 Orin executor non_monotonic_seq

现象：

```text
[orin phase3 executor] idx=50 seq=1 accepted=False publish=False reason=non_monotonic_seq
...
[orin phase3 executor] idx=50 seq=50 accepted=False publish=False reason=non_monotonic_seq
```

根因：

```text
executor 上一轮已经收到 seq=1..50。
x86 新 record 进程又从 seq=1 开始。
executor 防重放逻辑拒绝小于等于上次 seq 的 packet。
```

处理：

```bash
cd ~/workspace/flexible_lerobot

bash udp_test/server_bash/orin_arm/stop_phase3_executor.sh
EXECUTION=dry_run AUTO_TAIL=1 bash udp_test/server_bash/orin_arm/start_phase3_executor.sh
```

长期改进建议：

```text
协议可引入 session_id，使不同 record session 的 seq 空间隔离。
当前短期联调用重启 executor 清零 seq 状态。
```

## 6. 当前安全边界

必须继续遵守：

```text
1. x86 不 publish ROS topic，只发 UDP packet。
2. Orin executor 默认 dry_run。
3. dry_run 下 publish=False。
4. 真实 publish 不能靠“有人按急停”替代软件 gate。
5. armed 前必须配置并验证 conservative joint/gripper limits。
6. armed 前必须确认 topic allowlist。
7. armed 前必须确认单包、小幅、低频、短时。
8. 不允许直接 replay 未检查 action 内容的数据集。
9. 不允许 replay jz_robot_udp_constant 全 0 action 数据集到真机。
```

本次已证明 hold-action dataset 安全性优于 constant-zero dataset，但这不等于可以直接 replay active。下一步必须先做 armed 单包小偏移。

```text
3. x86 packet 也必须是 --execution armed。
4. topic 必须仍为四个 allowlist topic。
5. 首次 armed 只允许 count=1、hz 很低、delta_value=0.001 或更小。
6. 现场必须有人按急停，但急停只是兜底，不能替代前面软件检查。
```

建议第一条 active 测试不是 replay dataset，而是：

```text
current observation hold action + one joint tiny delta
```

并且：

```text
count=1
hz<=1
publish topic 只允许 arm/gripper allowlist
观察机器人方向和幅度
失败立即停 executor
```

### 7.3 暂不建议直接做的事

```text
1. 直接 replay 50 帧 dataset 到真机。
2. 直接把 executor armed 后跑 record 10 秒。
3. 使用 constant teleop 的全 0 action 数据集回放。
4. 在未确认 limits 和 topic allowlist 时 armed。
5. 同时打开 VR 控制和 UDP executor 做竞争控制。
```
