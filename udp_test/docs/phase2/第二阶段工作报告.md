# 第二阶段工作报告

本文档记录第二阶段 `JZRobotUDP` command dry-run 链路的开发结果，方便后续在 x86 与 Orin 之间继续联调。

当前阶段的核心结论：

```text
JZRobotUDP.send_action() 已经实现，但只允许 dry_run。
x86 可以验证 LeRobot action path 和 UDP command packet。
Orin 只接收、解码、校验、打印 command 日志。
Orin 不 publish ROS command topic，不 publish cmd_vel，不控制手臂、夹爪或底盘。
```

注意：本文档记录的是 Phase 2 当前完成状态。Phase 2 的本机 dry-run 和安全审查已经通过；x86/Orin 实机 command dry-run、`lerobot-record` dry-run 短 episode、Phase 1 `OBS_COUNT=600` 回归仍需要在实机链路上补充验收证据。

## 阶段目标

第一阶段已经完成 observation-only 链路：

```text
Orin / ARM:
  ROS2 state topic -> UDP state packet

x86:
  UDP state packet + RTSP camera -> JZRobotUDP.get_observation()
```

第二阶段的目标是在不让机器人运动的前提下，把 LeRobot action path 打通：

```text
x86 JZRobotUDP.send_action()
  -> action key / value 校验
  -> command packet v1 编码
  -> local dry-run log 或 UDP dry-run 发送
  -> Orin command receiver 接收
  -> sender IP / packet schema / seq 校验
  -> Orin 打印 DRY_RUN command 日志
  -> 到此为止
```

第二阶段明确不做：

```text
不把 command 转成 ROS command topic
不 create_publisher
不 publish(...)
不 publish cmd_vel
不控制机械臂
不控制夹爪
不控制底盘
不做 policy inference 实机控制
不把人工急停作为唯一安全机制
```

当前安全约束：

这一步的意义是把 `send_action()` 的接口能力补齐，但把执行模式固定在 Phase 2 的 dry-run 范围内。

### 2. 新增 command packet v1 协议

修改文件：

```text
src/lerobot/robots/jz_robot_udp/protocol.py
```

新增内容：

```text
COMMAND_MESSAGE_TYPE = "command"
COMMAND_MODE_DRY_RUN = "dry_run"

make_jz_robot_udp_command_packet(...)
encode_jz_robot_udp_command_packet(...)
decode_jz_robot_udp_command_packet(...)
validate_jz_robot_udp_command_packet(...)
```

command packet 使用 JSON UTF-8 编码，字段结构：

```json
{
  "version": 1,
  "type": "command",
  "robot": "robot1",
  "seq": 1,
  "stamp_ns": 123456789,
  "mode": "dry_run",
  "actions": {
    "left": {
      "left_joint1": 0.0
    },
    "right": {
      "right_joint1": 0.0
    },
    "grippers": {
      "left": {
        "width": 0.0,
        "force": 0.0
      },
      "right": {
        "width": 0.0,
        "force": 0.0
      }
    }
  }
}
```

协议校验覆盖：

```text
version/type
robot
seq
stamp_ns
mode=dry_run
actions.left
actions.right
actions.grippers.left/right
数值类型
bool 拒绝
NaN / inf 拒绝
```

当前 receiver 会检测 seq 单调递增；`stamp_ns` 当前校验存在和类型，不做基于当前时间的 stale-age 拒绝。由于 Phase 2 不执行动作，这不是当前安全阻塞；进入 Phase 3 前应再补时间窗安全门。

### 3. 新增 UDP command sender

修改文件：

```text
src/lerobot/robots/jz_robot_udp/udp_client.py
```

新增类：

```text
UDPCommandSender
```

作用：

```text
只负责把已经编码好的 dry-run command bytes 通过 UDP sendto() 发到目标 IP/port。
不接收 state。
不 import ROS。
不 publish ROS message。

```

状态接收和 command 发送保持分离：

```text
UDPStateReceiver:
  bind + recvfrom state packet

UDPCommandSender:
  sendto command packet
```


`send_action()` 当前行为：

```text
1. 校验 action keys 必须精确匹配 action_features
2. 拒绝 missing key
3. 拒绝 extra key
4. 拒绝 bool / 非数值
5. 转成 float action copy
6. seq 自增
7. 固定 mode=dry_run
8. 生成 command packet
9. local 模式只打印 DRY_RUN 日志
10. udp 模式只发送 dry-run UDP packet
11. 返回 float action copy
```

`send_action()` 不做：

```text
不调用 ROS
不调用机器人底层 API
不 publish command topic
不 publish cmd_vel
不控制真实机器人
```

## 当前安全边界

当前软件安全边界由多层约束组成：

```text
1. 配置层：
   send_action_execution 必须等于 dry_run。

2. 协议层：
   command packet mode 必须等于 dry_run。

3. x86 Robot 层：
   send_action() 固定使用 COMMAND_MODE_DRY_RUN 组包。

4. x86 UDP 层：
   UDPCommandSender 只 sendto bytes，不包含 ROS 或机器人 API。

5. Orin receiver 层：
   只 socket recvfrom + decode + validate + print。

6. 单测层：
   AST 检查禁止 rclpy、create_publisher、publish、cmd_vel 控制路径。
```

因此当前 Phase 2 可以验证 command 链路，但不能触发真实机器人动作。
